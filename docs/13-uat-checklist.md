# ۱۳. معیارهای پذیرش (UAT) و چک‌لیست راه‌اندازی

## ۱۳-۱. سطوح پذیرش

| سطح | نام | هدف | مجری | معیار عبور |
|---|---|---|---|---|
| L1 | تست واحد/اجزا (SIT) | صحت هر ماژول به‌تنهایی | تیم فنی | ۱۰۰٪ موارد تستِ بحرانی موفق |
| L2 | تست یکپارچه‌سازی | صحت جریان بین دو سیستم | تیم یکپارچه‌سازی | بدون رویدادِ گم‌شده/مضاعف؛ انطباق قراردادها |
| L3 | تست پذیرش کاربر (UAT) | کارآمدی در کار واقعی | کاربران واقعی با سناریوی واقعی | امضای نمایندگان واحدها |
| L4 | تست عملکرد و بار | پایداری در بار واقعی | تیم فنی | رعایت NFR (زمان پاسخ، هم‌زمانی) |
| L5 | تست امنیت و انطباق | عدم وجود آسیب‌پذیری بحرانی | مشاور امنیت + حسابرس | بدون یافتهٔ بحرانیِ باز |
| L6 | اجرای موازی (Parallel Run) | تطبیق خروجیِ جدید با روش قدیم | واحدها | انحراف زیر آستانه (مثلاً موجودی < ۲٪) |
| L7 | راه‌اندازی نرم (Go-Live) | انتقال به سیستم جدید | همه | چک‌لیست Go-Live کامل |
| L8 | پایش پس از راه‌اندازی (Hypercare) | پایداری در ۳۰ روز نخست | تیم پروژه + پشتیبانی | روند رو‌به‌بهبودِ خطاها و زمان پاسخ |

## ۱۳-۲. سناریوهای UAT سرتاسری (End-to-End)

هر سناریو باید **بدون هیچ ورود دستیِ تکراری** و **با ردیابی کامل** اجرا شود.
معیار عبور: انجامِ موفق + وجودِ رکورد حسابرسی با `correlation_id` یکتا در کل مسیر.

| # | سناریو | مسیر | معیار عبور دقیق |
|---|---|---|---|
| UAT-01 | دریافت مادهٔ اولیه تا مصرف | ASN → گیت/باسکول → نمونه → QC → آزادسازی → مکان‌یابی → برداشت FEFO → مصرف در خط | کسر موجودی در همان لحظهٔ اسکن؛ مغایرت موجودی صفر |
| UAT-02 | تولید بچ تا ترخیص | دریافت برنامه → آماده‌سازی خط → صدور WO → مصرف → پارامترها → نمونه → QC → ترخیص → COA | OEE ثبت‌شده؛ شجره‌نامه کامل؛ COA با دادهٔ واقعی |
| UAT-03 | قرنطینه و رد | نتیجهٔ نامنطبق → قرنطینه خودکار → جلوگیری از برداشت/ارسال | تلاشِ برداشت/ارسال با خطا مواجه و در Audit ثبت شود |
| UAT-04 | ارسال محصول | سفارش → تخصیص → Pick → SSCC → اسناد → تأیید انبار → تأیید حراست → بارگیری → POD | بدون تأیید دومرحله‌ای، دروازه باز نشود |
| UAT-05 | ردیابی و فراخوان | انتخاب بچ → گراف عقب/جلو تا مشتری | پاسخ در ≤ ۳۰ ثانیه؛ خروجی شامل مشتریان و مقادیر |
| UAT-06 | خرابی تجهیز و PM | آلارم → WO خودکار → PTW/LOTO → رزرو قطعه → اجرا → بستن → هزینه | بدون PTW، شروع WO مسدود؛ مصرف قطعه روی WO ثبت شود |
| UAT-07 | تردد و حضور | کارت‌زنی → حضور → شیفت → تخصیص به خط → گیتِ صلاحیت | اپراتورِ فاقد گواهی نتواند روی WO ثبت کند |
| UAT-08 | خروج کالا و کنترل حراست | درخواست خروج → تطبیق ۴شرطی → مجوز/قفل | حذف یک شرط ⇒ دروازه باز نشود |
| UAT-09 | رویداد مالی خودکار | تولید/مصرف → سند حسابداری → بهای تمام‌شده | سند با ارجاع به رویداد مبدأ؛ امکان دریل‌داون |
| UAT-10 | حالت آفلاین کارگاه | قطع شبکه → ادامهٔ ثبت → اتصال مجدد → همگام‌سازی | بدون از دست رفتن و بدون ثبت مضاعف |
| UAT-11 | اضطرار و تخلیه | اعلام اضطرار → آزادسازی گیت‌ها → نقشهٔ حضور | همهٔ گیت‌ها ظرف ≤ ۳۰ ثانیه Fail-safe شوند |
| UAT-12 | کنترل تغییر Recipe | تلاش تغییر در HMI → قفل → ثبت رخداد | تغییر بدون امضای دوم اعمال نشود |

## ۱۳-۳. معیارهای پذیرش کمی (Acceptance Criteria)

| حوزه | معیار | آستانه | روش اندازه‌گیری |
|---|---|---|---|
| **عملکرد** | زمان پاسخ UI (عملیات رایج) | < ۱ ثانیه (p95) | ابزار APM روی ۵۰ کاربر هم‌زمان |
| عملکرد | نمایش مقدار لحظه‌ای در SCADA | < ۵۰۰ میلی‌ثانیه | اندازه‌گیری انتها‌به‌انتها |
| عملکرد | تأخیر رویداد تولید تا MES | < ۵ ثانیه (p95) | سنجهٔ Kafka lag |
| عملکرد | به‌روزرسانی داشبورد مدیریتی | < ۵ دقیقه | مانیتور خط لولهٔ داده |
| **در دسترس‌بودن** | سامانه‌های L2/L3 | ≥ ۹۹٫۹٪ ماهانه | مانیتورینگ |
| در دسترس‌بودن | حالت آفلاین ایستگاه‌های کارگاهی | ۷۲ ساعت عملیات کامل | تست قطع عمدی |
| **داده** | دقت موجودی انبار | ≥ ۹۸٪ | شمارش دوره‌ای |
| داده | صحت ردیابی بچ (تست کور) | ۱۰۰٪ در ۱۰ نمونه | ممیزی |
| داده | رویدادهای گم‌شده/مضاعف | ۰ | انطباق شمارش رویدادها |
| داده | کیفیت دادهٔ پایه | ≥ ۹۸٪ | قواعد MDM |
| **امنیت** | یافته‌های بحرانی تست نفوذ | ۰ باز (همه بسته یا پذیرش مستند) | گزارش تست نفوذ |
| امنیت | حساب‌های بدون MFA در L3/L4 | ۰ | گزارش SSO |
| امنیت | پوشش Audit Trail برای تراکنش‌های بحرانی | ۱۰۰٪ | بازبینی لاگ‌ها |
| **انطباق** | امضای الکترونیکی روی ترخیص/تأیید | ۱۰۰٪ | ممیزی |
| انطباق | تغییرناپذیری لاگ حسابرسی | اثبات‌شده با تست دستکاری | تست نفوذِ لاگ |
| **پذیرش کاربر** | نرخ تکمیل وظایف در UAT بدون راهنمایی | ≥ ۹۰٪ | ثبت در جلسات UAT |
| پذیرش کاربر | امتیاز رضایت (SUS) برای صفحات کلیدی | ≥ ۶۸ از ۱۰۰ | پرسش‌نامه |
| **یکپارچگی** | درصد اسناد مالی خودکار | ≥ ۹۰٪ در ۳ ماه | گزارش ERP |

## ۱۳-۴. چک‌لیست راه‌اندازی (Go-Live Checklist)

### الف) آمادگی داده

- [ ] ≥ ۹۵٪ اقلام کلاس A در MDM تعریف و تأیید شده
- [ ] درخت دارایی کامل شده و BOM تجهیز برای دارایی‌های کلاس A ثبت شده
- [ ] موجودی اولیه انبارها شمارش و در WMS بارگذاری شده (با تاریخِ انطباق)
- [ ] مغایرت موجودی اولیه زیر ۲٪
- [ ] مشتریان، تأمین‌کنندگان و کالاها با کدهای GS1 برچسب‌گذاری شده
- [ ] برنامهٔ PM برای دارایی‌های کلاس A تعریف شده
- [ ] داده‌های تاریخیِ موردنیاز (حداقل ۱۲ ماه) برای تحلیل مهاجرت داده شده

### ب) آمادگی فنی

- [ ] همهٔ رابط‌ها در محیط تولید تست و تأیید شده (با دادهٔ واقعی)
- [ ] صف خطا (DLQ) خالی و مانیتورینگ آن فعال
- [ ] پشتیبان‌گیری کامل انجام و **یک بازیابی آزمایشی موفق** ثبت شده
- [ ] مانیتورینگ، هشدارها و داشبورد سلامت زیرساخت فعال
- [ ] DR سناریو تست‌شده با RPO/RTO تأییدشده
- [ ] همهٔ تجهیزات OT دارای موجودی دارایی (Asset Inventory) و در شبکهٔ OT شناسایی‌شده
- [ ] پوشش بی‌سیم در تمام نقاط کاری با Site Survey تأیید شده (سیگنال ≥ −۶۵ dBm)

### ج) آمادگی امنیت

- [ ] زون‌ها و کاندویت‌ها مستند و فایروال‌ها اعمال شده
- [ ] MFA برای همهٔ حساب‌های L3/L4 و مدیران فعال
- [ ] همهٔ رمزهای پیش‌فرض تجهیزات تغییر کرده
- [ ] دسترسی‌های پیمانکاران زمان‌دار و محدود شده
- [ ] سیاست نگه‌داری لاگ و Audit فعال و انبار WORM تنظیم شده
- [ ] تست نفوذ انجام و یافته‌های بحرانی بسته شده

### د) آمادگی سازمانی

- [ ] آموزش نقش‌محور برای ≥ ۹۵٪ کاربران انجام و ثبت شده
- [ ] رهبران تغییر در هر واحد مشخص و در دسترس (Hypercare)
- [ ] فرم‌ها و رویه‌های کاغذیِ قدیمی جمع‌آوری و غیرفعال شده
- [ ] مستندات (راهنمای کاربر، Runbook، نقشهٔ شبکه، دفترچهٔ API) تحویل شده
- [ ] برنامهٔ پشتیبانیِ ۳۰ روزه (Hypercare) با شیفت و SLA پاسخ اعلام شده
- [ ] مسیر بازگشت (Rollback) برای هر سامانه تعریف و تست شده

### هـ) روز راه‌اندازی

- [ ] توقف برنامه‌ریزی‌شدهٔ تولید اعلام و هماهنگ شده
- [ ] موجودیِ نقطه‌ای (Cut-over Snapshot) گرفته شده
- [ ] ترتیبِ انتقالِ سامانه‌ها مستند و اجرا شده
- [ ] انطباقِ موجودی پس از راه‌اندازی تأیید شده
- [ ] اولین بچ با موفقیت ثبت، ردیابی و ترخیص شده
- [ ] جلسهٔ روزانهٔ «گذر از بحران» برای ۱۴ روز نخست برنامه‌ریزی شده

## ۱۳-۵. معیار خروج از دورهٔ Hypercare (۳۰ روز)

| معیار | آستانه |
|---|---|
| تعداد حادثهٔ بحرانیِ باز | ۰ |
| میانگین زمان پاسخ به تیکت‌های بحرانی | < ۳۰ دقیقه |
| درصد ثبت‌های دستی (کارهای دور زدن) | روند کاهشی و < ۱۰٪ |
| رضایت کاربران کلیدی | ≥ ۷۰٪ امتیاز مثبت |
| در دسترس‌بودن سامانه‌ها | ≥ ۹۹٫۵٪ در دوره |
| تعداد رویدادهای در صف خطا | ۰ در ۷ روز پیاپی |
