# ۴. ماتریس یکپارچگی بین‌واحدی (Integration Matrix)

> این مستند به‌طور خودکار از `data/integration_matrix.csv` تولید می‌شود (`python3 tools/build_integration_matrix.py`).
> برای تغییر هر رابطه، **CSV را ویرایش کنید**؛ جدول‌ها و آمار خودکار به‌روز می‌شوند.

## ۴-۱. راهنمای خواندن ماتریس

هر خانهٔ ماتریس شامل سه بخش است: `جهت` + `مکانیزم` · `فرکانس` + نشان حساسیت.

| نماد | معنا |
|---|---|
| `→` | جریان یک‌طرفه (از سطر به ستون) |
| `↔` | جریان دوطرفه |
| `API` | رابط برنامه‌نویسی (REST/gRPC) — درخواست/پاسخ همزمان |
| `EV` | رویداد از طریق ستون فقرات پیام (Kafka/MQTT) — ناهمزمان |
| `OPC` | OPC UA (یا MQTT/Sparkplug از لبه) برای دادهٔ OT |
| `File` | تبادل فایل/سند (SFTP/EDI) برای اسناد رسمی و گمرکی |
| `DB` | بارگذاری مستقیم در انبار داده برای تحلیل |
| `RT` | فرکانس: بلادرنگ (زیر ثانیه تا چند ثانیه) |
| `MIN` | فرکانس: دقیقه‌ای |
| `H` | فرکانس: ساعتی |
| `D` | فرکانس: روزانه |
| `W` | فرکانس: هفتگی |
| `M` | فرکانس: ماهانه |
| `SH` | فرکانس: شیفتی |
| `OE` | فرکانس: رویدادی |
| `*` | رابطهٔ **بحرانی**: قطع آن بلافاصله تولید یا انطباق را متوقف می‌کند |
| `—` | تبادل مستقیم تعریف‌نشده — در صورت نیاز، از مسیر غیرمستقیم (MDM/BI/ERP) استفاده می‌شود |

> **قاعدهٔ طلایی ماتریس:** هیچ خانه‌ای بدون پاسخ نمی‌ماند. خانه‌های `—` به معنای «نیازی به رابطه نیست» است، نه «نامعلوم». عدم قطعیت در این ماتریس پذیرفته نیست؛ اگر رابطه‌ای هنوز تعریف نشده، باید به‌عنوان «تعریف‌نشده — نیازمند تصمیم» در [`16-open-questions.md`](16-open-questions.md) ثبت شود.

## ۴-۶. جریان‌های الزامی (پوشش صریح)

یازده جریانِ زیر باید **بدون ابهام** پیاده‌سازی شوند. ردیف هر کدام در جدول‌های بالا قابل جست‌وجو است.

| # | جریان الزامی | مبدأ | مقصد | شرح اجرا |
|---|---|---|---|---|
| 1 | تولید → انبار مواد | PRD | RMW | کسر خودکار مصرف به‌ازای دستور کار: با اسکن بارکد و توزین در ایستگاه خط، رویداد `material.consumed` صادر و موجودی همان لحظه کسر می‌شود؛ تلورانس ±۱.۵٪ [فرض] و کنترل FEFO پیش از کسر. |
| 2 | تولید → انبار محصول | PRD | FGW | اعلام بچ آماده و انتقال به انبار: پس از ترخیص QC، رویداد `batch.completed` با کد بچ، مقدار، SSCC و مشخصات ارسال می‌شود؛ بدون `released` انتقالی انجام نمی‌شود. |
| 3 | QC → انبارها | QCL | RMW / FGW | گیت کیفیت: سه وضعیت `released / rejected / quarantine` به‌صورت قفل سیستمی عمل می‌کند؛ مادهٔ قرنطینه قابل برداشت نیست و محصول قرنطینه قابل ارسال نیست. |
| 4 | انبار محصول → حراست | FGW | SEC | مجوز خروج کالا: تطبیق چهارگانه (بارنامه/فاکتور/تأیید انبار/QC) پیش از صدور مجوز؛ هر شرط ناقص ⇒ دروازه باز نمی‌شود. |
| 5 | انبار محصول → بازرگانی | FGW | SAL | تأیید ارسال و بارنامه: SSCCها، پکینگ‌لیست و e-POD به سفارش فروش متصل می‌شوند و صدور فاکتور را آزاد می‌کنند. |
| 6 | CMMS → تولید | MNT | PRD | درخواست کار و توقف برنامه‌ریزی‌شده: WO پنجرهٔ توقف را در برنامهٔ تولید رزرو می‌کند؛ توقفِ اضطراری بلافاصله در MES ثبت و در OEE لحاظ می‌شود. |
| 7 | CMMS → انبار فنی | MNT | MRO | مصرف قطعه: صدور فقط با شمارهٔ WO باز؛ رزرو خودکار هنگام برنامه‌ریزی و کسر هنگام ثبت مصرف. |
| 8 | HR → تولید | HRM | PRD | تخصیص اپراتور واجد صلاحیت: بررسی مهارت، گواهی و سلامت در لحظهٔ ثبت روی دستور کار؛ نقض ⇒ قفل ثبت و پیشنهاد جایگزین. |
| 9 | HSE → حراست | HSE | SEC | هشدار اضطراری و تخلیه: با اعلام وضعیت اضطراری، همهٔ گیت‌ها Fail-safe می‌شوند و فهرست حاضران در نقاط تجمع نمایش داده می‌شود. |
| 10 | همه → مالی | * | FIN | رویداد مالی خودکار: هر رویداد عملیاتیِ اثرگذار یک رویداد `fin.posting` با `correlation_id` یکتا تولید می‌کند تا از صورت مالی تا رکورد سنسور قابل ردیابی باشد. |
| 11 | همه → BI | * | BI | دادهٔ تحلیلی برای داشبورد مدیریت: انتشار رویدادها در انبار داده با لایهٔ معنایی یکسان (تعریف واحد برای هر شاخص) و تأخیر هدف زیر ۵ دقیقه. |

## ۴-۷. الگوهای یکپارچگی (Integration Patterns)

| الگو | کِی استفاده می‌شود | مثال در این پروژه | دلیل |
|---|---|---|---|
| **رویداد (Event/Async)** | تغییر وضعیتی که چند سیستم باید از آن مطلع شوند و فرستنده نباید منتظر بماند | `material.consumed` → WMS، ERP، مالی، BI | جداسازی، مقیاس‌پذیری، تحمل خطا |
| **API همزمان (Request/Reply)** | نیاز به پاسخ قطعی پیش از ادامه (گیت/تأیید) | استعلام صلاحیت اپراتور از HRM پیش از ثبت کار | قطعیت و سادگی خطا |
| **OPC UA / MQTT** | دادهٔ OT از لایهٔ ۱/۲ به ۳ | تله‌متری PLC، لرزش، پاورمتر | استاندارد OT، مدل اطلاعاتی، امنیت |
| **فایل/EDI** | اسناد رسمی و برون‌سازمانی با قالب قانونی | اظهارنامهٔ گمرکی، صورت‌حساب مالیاتی | الزام قانونی و قطعیت سند |
| **بارگذاری در انبار داده** | حجم بالا برای تحلیل (بدون تأثیر بر تراکنش) | تاریخچهٔ تله‌متری و نتایج آزمون برای BI | کارایی و جداسازی بار |
| **همگام‌سازی دادهٔ پایه (MDM)** | تغییر در موجودیت‌های پایه | تعریف کالای جدید → انتشار به ERP، MES، WMS | یکپارچگی معنایی |

## ۴-۸. ضدالگوهای ممنوع (Anti-Patterns)

| ضدالگو | چرا ممنوع | جایگزین |
|---|---|---|
| اتصال نقطه‌به‌نقطهٔ مستقیمِ پایگاه‌داده‌ها | وابستگی پنهان، شکستن با هر تغییر اسکیما | API یا رویداد با قرارداد نسخه‌دار |
| فایلِ اکسلِ دستی به‌عنوان رابط | بدون ردیابی، بدون زمان، مستعد خطا | فرم/API |
| انتشار مستقیم از OT به IT (بدون DMZ) | نقض صریح IEC 62443 | عبور از DMZ با لیست سفید |
| رویدادِ بدون `idempotency_key` | ثبت مضاعف در تلاش مجدد و حالت آفلاین | کلید یکتای باید |
| ارسال دادهٔ حساسِ پرسنلی در رویداد عمومی | نقض حریم خصوصی | فقط شناسه؛ جزئیات با API مجاز |
| «دور زدن موقت» با ثبت دستی در ERP | شکستن زنجیرهٔ ردیابی | ثبت اصلاحیِ مستند با دلیل |
