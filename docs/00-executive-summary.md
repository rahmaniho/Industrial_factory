# ۰. خلاصهٔ مدیریتی (Executive Summary)

> مخاطب: هیئت‌مدیره / کمیتهٔ راهبری · زمان مطالعه: ۸ دقیقه · سطح: تصمیم‌سازی

## ۰-۱. چرا این پروژه

کارخانه امروز «تولید می‌کند» اما «نمی‌داند چگونه تولید می‌کند». چهار گسستِ داده‌ایِ مشخص:

| گسست | نشانهٔ میدانی | هزینهٔ پنهان |
|---|---|---|
| ماشین → سرپرست | آمار تولید روی کاغذ، تلفیق در انتهای شیفت | OEE واقعی نامعلوم؛ توقف‌های ۵ دقیقه‌ای دیده نمی‌شوند |
| تولید → انبار/QC | درخواست کالا با تلفن؛ فرم QC کاغذی | موجودی غیرواقعی؛ مصرف مواد با تأخیر کسر می‌شود |
| عملیات → مالی | بهای تمام‌شده در پایان ماه، با تخصیص سرباری تخمینی | قیمت‌گذاری اشتباه؛ انحراف بودجه دیر کشف می‌شود |
| کل زنجیره → مشتری/ممیز | ردیابی بچ ۴ ساعت؛ بستهٔ ممیزی در ۲ هفته جمع می‌شود | ریسک فراخوان (Recall) و جریمهٔ عدم انطباق |

## ۰-۲. چه می‌سازیم (به زبان غیر فنی)

یک «سیستم عصبی» برای کارخانه:

- **حسگرها و PLCها** (اعضای حسی) ضربان خط را پیوسته می‌فرستند.
- **Historian + MES** (حافظه و مخچه) هر پالت، هر بچ، هر توقف را با زمان و عامل ثبت می‌کنند.
- **WMS/CMMS/HSE** (اندام‌ها) هر کدام کار خود را می‌کنند اما روی «یک زبان مشترک» از دادهٔ پایه.
- **ERP/BI** (قشر تصمیم) دیگر آمار را از کسی نمی‌پرسد؛ از رویدادها می‌گیرد.

قانون طلایی پروژه: **هیچ داده‌ای دوبار وارد نشود، هیچ تأییدی شفاهی نماند، هیچ تغییری پاک نشود.**

## ۰-۶. حاکمیت پروژه

| نقش | مسئولیت | تصمیمات اختصاصی |
|---|---|---|
| حامی (Sponsor) — مدیرعامل | بودجه، رفع گلوگاه‌های بین‌واحدی | توقف/ادامهٔ فاز |
| مدیر پروژه (PMO) | زمان‌بندی، ریسک، قراردادها | تخصیص منابع |
| معمار کل (Chief Architect) | رعایت ADRها، استانداردها | انحراف از معماری |
| مالکان Master Data (Data Owners) | کیفیت دادهٔ پایهٔ حوزهٔ خود | تعریف/تغییر موجودیت |
| رهبران تغییر (Change Champions) در هر واحد | پذیرش کاربران | اولویت‌بندی بهبودهای UI |
| افسر امنیت OT (OT Security Officer) | IEC 62443، زون/کاندویت | وتوی اتصال جدید |

**جلسهٔ هفتگی راهبری** با ۵ عدد: ٪پیشرفت فاز، تعداد بلوکرها، ٪کیفیت Master Data،
تعداد انحراف از ADR، ریسک‌های قرمزِ باز.

## ۰-۷. سه تصمیمی که امروز باید گرفته شود

1. **تأیید پایلوت**: کدام خط به‌عنوان پایلوت فاز ۲ انتخاب می‌شود؟ (پیشنهاد: خطی که بیشترین
   تناژ × بیشترین توقف × بیشترین ریسک کیفیت را دارد.)
2. **تأیید مدل تأمین**: یکپارچه‌ساز (SI) واحد یا چند تأمین‌کنندهٔ بهترینِ بازار؟
   (پیشنهاد: SI واحد با قرارداد مشارکتی + الزام تحویل مستندات و API باز.)
3. **تأیید «قفل‌های سیستمی»**: آیا مدیریت آمادگیِ پذیرش این را دارد که خروج کالا بدون
   تأیید دوگانه، **توسط سیستم متوقف شود** — حتی اگر مشتری منتظر باشد؟ (بدون این بند،
   بخش بزرگی از ارزش پروژه از دست می‌رود.)
